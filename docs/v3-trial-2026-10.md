# v3 試行：controller 預設自己做（2026-10）

> 本檔記錄 v3 的動機、試行窗口、指標門檻與 v2 基線。結論是**待試行的假設**，不是已證實的節省。規則本體在 `global/claude/route-card.md`、`global/shared/skills/dispatch/SKILL.md` §1「必派條件」與 `global/codex/rules/dispatch.md` §1「派工判斷」。
> 專案以代號稱呼（對照只存本機，規則見 `.claude/skills/maintain-guideline/SKILL.md` §3）。

## 動機

v2 的預設是「controller 派工、worker 實作」。使用者依 Anthropic 文章〈when to fold subagents into your main agent loop〉決定改版：controller 預設在主對話自己做，只在必派條件成立時派 subagent。文章反對按問題類型或組織圖切 subagent（每次交接都是傳話遊戲）；subagent 仍該用的三個條件是 (a) 單一 loop 出現可量測的 context 膨脹退化、(b) 需要平行且用完即丟的 fresh context、(c) 單一 agent 選錯工具或 prompt 自相矛盾。v3 據此不再把「任務可獨立、只需結論」當派工理由，也不按工作類型切（實作、文件、測試各派一個）。

v3 把這些落成 dispatch skill §1 的四條必派條件（(a) 對應條件 1、(b) 對應條件 2，(c) 對應條件 3 的工具或指示衝突，條件 4 黑箱驗收是 (b) 的 fresh context 用法）：context 膨脹（含主對話 ≥300K 且還有實作 phase）、平行且用完即丟、工具或指示衝突（CI／release 設定、非主對話 model）、黑箱驗收。

**刻意不動**三項，理由是它們不是「按問題類型切」，交接的是「產物＋驗收條件」而不是「設計意圖」，沒有傳話失真：

- `verifier`：對應黑箱驗證，也是用完即丟的 fresh context。製作脈絡本身是偏誤來源，摺回主對話等於自驗；v3 讓 controller 變成製作者，這條反而更要緊。
- `Explore`：對應獨立研究路徑與條件 (a)。掃描的原始輸出之後不再引用，留在主對話會被主對話模型每輪重讀，這是 69% 重讀成本的來源。
- fresh `code-review`：同 verifier，屬黑箱驗證；主對話自跑 `Skill(code-review)` 帶著製作 context，不算 fresh。

## 混淆因子與控制

- **任務組成**：分 S／M／L 組比；V 的 L 組占比和 B 差 >20pp 時只比分組結果。前 3 大專案分開列。
- **模型版本**：從 `cost` 的 model 表記錄各窗口的 model ID 與 `sessions.version`。主對話、worker 或 verifier 的 model ID 在 V 中途變了，就在變更點切窗口，只比變更前那段。
- **同期制度改動**：V 期間凍結 `global/**` 其他行為類 commit（見上）。
- **其他來源**：用量包含其他裝置、claude.ai 與 Codex，本機量不到；判定前先問使用者。
- **v3 實作本身**：實作 v3 的 session 用 `--exclude-session` 排除。
- **窗口邊界**：B 終點與 V 起點附近的在途 subagent 只有一半落在窗口內；T0 選在無在途 subagent 時刻，否則註明誤差。B 的起點附近也可能有在途 subagent。
- **啟發式與口徑**：`verdict_heuristic`、`bash_writes_heuristic`、過期重寫、平行度、`out_est`／`cost_est` 都是啟發式；重要結論抽樣回頭核對原文。比相對占比與前後變化，不跨機器、跨期間比絕對值。
- **verifier 判定的歸因**：抽 10 個 OPEN 人工分類「交接失真」或「實作錯」，預期交接失真占比下降；此項不設門檻。

## 已決事項

- **context 門檻 300K**（使用者核定）。理由：v2 主對話 context 中位 168K、P90 303K（>400K 的 request 只占 1.8%），300K 約在 v2 的 P90，只切掉長尾，不讓一般 session 提早派出。
- **Codex 端同一輪同步改**（使用者核定）。Codex 主對話 tier 可能比 Luna 貴，但其成本本機量不到；由使用者在 Codex 端另行確認，不列入上表指標。Codex 沒有 context 用量指示時，「本 session 已 compact 過」代替 300K 訊號是**未驗證的代替訊號**。
- **路由卡刪除清單全部照刪**（使用者核定）：「不下場做粗活」；「任務可獨立且主對話只需結論」（按類型切，正是文章反對的）；「探索與決策需即時互動時留在主對話」（預設已自己做）；「## 自行動手」整節（CI 那句併進條件 3）；標題裡的「（SessionStart 注入…不繼承）」（hook 印出的標頭已寫）；派工授權裡的列舉「（驗收、掃描、探索、規劃、實作）」。路由卡 2,979 bytes，在 3,000 bytes 的 tripwire 內。
